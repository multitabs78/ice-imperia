# Проверки

Две независимые проверки. На хостинг папка `tests/` не загружается.

## Серверная часть — `php tests/run.php`

Нужен только PHP. Поднимает встроенный сервер на тестовой базе SQLite
и ходит по адресам API настоящими запросами: вход паролем и кодом,
просроченный код, счётчик неверных попыток, ограничение перебора, границы
доступа родителя и администратора, выход, смена пароля, записи в журнале.

Схема базы берётся из `db/migrations/*.sql` — той же единственной, что
применяется на хостинге, — и переводится на диалект SQLite на лету
(`tests/sqlite.php`). Второй копии схемы в проекте нет: она бы разошлась
с первой.

## Страница входа — `node tests/browser.js`

Нужны Node.js и Playwright с Chromium. Открывает `/cabinet/login.html`
в настоящем браузере на размере телефона и проходит вход: выбор канала,
ввод кода, ошибки, вход по паролю, выход, память о входе после
перезагрузки. Снимки экранов складываются в `tests/screenshots/`.

Перед запуском нужен сервер с тестовой базой:

```sh
# 1. Создать базу и записать в неё администратора и родителя
php tests/seed-browser.php

# 2. Поднять сервер
IMPERIA_TEST_DB=/tmp/imperia-tests/login.sqlite \
IMPERIA_ROOT="$PWD" \
PHP_CLI_SERVER_WORKERS=8 \
php -S 127.0.0.1:8921 -t . \
    -d auto_prepend_file="$PWD/tests/bootstrap.php" \
    -d sendmail_path="cat > /tmp/imperia-tests/mail.txt" \
    tests/router.php &

# 3. Прогнать проверки
node tests/browser.js
```

`sendmail_path` подменяет отправку почты: без него система честно отвечает,
что письмо не ушло, и до ввода кода дело не доходит.

`tests/router.php` подменяет mod_rewrite, которого нет у встроенного сервера,
и умеет показывать текущий код входа — поэтому без переменной
`IMPERIA_TEST_DB` он отвечает «Not found» и ничего не делает.
